# 0.1.0-alpha.5

0.1.0-alpha.5 は、文書ごとの役割を明確にし、その役割に沿って文書を保守、監査する手順を追加する。
アプリケーションの実装と利用時の挙動は 0.1.0-alpha.4 から変更しない。
0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## API 世代

設定 API は `agent-dock/config/v1alpha3`、JSONL イベント形式は `agent-dock/events/v1alpha2` であり、0.1.0-alpha.4 から変更しない。
製品版の更新だけを理由に設定またはイベントを作り直す必要はない。
非対応の設定またはイベントを検出した場合の既定値 No の確認と退避手順も変更しない。

## 文書体系

README を文書体系の入口とし、各文書の読み手、時間範囲、効力、具体度を区別する。
VISION は長期的な規範、DESIGN は 0.1.0 の設計上の制約、README は現在の利用方法、リリース文書は特定版で成立した事実を扱う。
DEPENDENCIES と AGENTS は、それぞれ依存関係と作業エージェントへ横断的な規則を課す。
未決事項と将来の作業候補は GitHub Issue に置く。

各 alpha の実装範囲と成立時点の挙動はリリース文書へ集約し、DESIGN から個別版の実装履歴を除く。

## 文書保守とリリース監査

文書の作成と改訂では、追加する記述の所属先を決め、同じ決定や事実を複数の文書で再定義しないための保守手順を追加する。
この手順は、変更対象と関係する文書を全文で読み、現在の挙動を扱う場合は実装とテストまで確認する。

リリース監査では、README、VISION、DESIGN、DEPENDENCIES、対象リリース文書を全文で突き合わせる。
個別リリースの実装履歴や現在の完成状況が規範文書へ混ざっていないかを、リリース前の確認対象に加える。

## 維持する挙動

タスクの入力と再編集、実行プロファイル、評価イベント、スコアカード、実行直後と過去実行の受け入れ判定は 0.1.0-alpha.4 から変更しない。
実支出は引き続き取得せず、助言も実装しない。
