# v0.0.1

v0.0.1 は、実際の仕事から評価に必要な観測を貯めるため、評価イベントの追記と受け入れ判定を実装する。
スコアカード、助言、過去の判定を訂正する入口、実支出の取得は実装しない。
対応 OS は macOS に限り、ほかの OS での動作は保証しない。

## スキーマと保存場所

設定とイベントの `schema_version` には、実装と同じ `0.0.1` を使う。
v0.0 が完成するまでは実装方式の探索を優先するため、異なるバージョンのスキーマは読み替えず、移行もしない。

既存の設定が異なるバージョンを持つ場合、agent-dock はプロンプト記録の可否を確認し、現在版の既定設定を一時ファイルへ書き込む。
置換直前の再検証で旧設定が変化していない場合だけ、旧設定全体を同じディレクトリへバックアップしてから、一時ファイルを旧設定へ原子的に置き換える。
複数プロセスによる設定の置換は、削除せずに維持する `config.toml.lock` で直列化する。
警告にはバックアップ先を表示する。
確認の中断、書き込みの失敗、旧設定の変化が起きた場合は、旧設定を残す。
新規作成または置換した設定ファイルの権限は `0600` とする。

イベントは `~/Library/Application Support/agent-dock/events.jsonl` へJSONL形式で保存する。
新規イベントファイルと `events.jsonl.lock` の権限は `0600` とする。
複数プロセスの読み込みは、削除せずに維持する `events.jsonl.lock` の共有ロックで競合を制御する。
追記と削除は同じファイルの排他ロックで競合を制御する。
異なるバージョンのイベントを検出した場合は、現行イベントが混在していてもイベントログ全体を同じディレクトリへバックアップし、元のログを削除して空の履歴から続行する。
混在していた現行イベントもバックアップには残るが、切り替え後の履歴からは外れる。
警告にはバックアップ先を表示する。
バックアップ前にイベントログが変化した場合は、変更後のログを読み直して処理する。
JSONとして壊れた行、`schema_version` が欠落した行、`schema_version` が文字列でない行、現在版として解釈できない行だけの場合はバックアップせず、警告を表示して読み飛ばす。

各行は、イベントとタスクのUUIDv7、UTCの発生時刻、イベント種別、種別ごとのデータを持つ。

```json
{"schema_version":"0.0.1","event_id":"019...","task_id":"019...","occurred_at":"2026-08-02T14:00:00Z","kind":"task_received","data":{"tags":["rust"],"prompt":null,"prompt_chars":12}}
```

## 評価イベント

agent-dock は次の四種類を記録する。

- **タスク受領**：自由タグ、プロンプト本文または `null`、プロンプトの文字数を記録する。
- **指名**：ユーザーが実行を確認したプロファイルの識別子を記録する。
- **実行**：実際に使ったプロファイル、作業ディレクトリ、開始時刻、所要時間、終了状態を記録する。
- **受け入れ判定**：対象の実行イベントと、受け入れまたは拒否を記録する。

実行プロファイルには、PATH探索または明示指定から解決した絶対実行パス、モデル、設定した追加引数を含める。
環境変数、agent-dock が内部で組み立てた引数列、標準出力、標準エラー、成果物は記録しない。
プロンプトの `null` は記録しなかった状態を表し、空文字列とは区別する。
通常の対話では空のタスク入力を拒否するため、空文字列のプロンプトは記録しない。

実支出はv0.0.1では取得せず、実行イベントの `cost` を常に `null` とする。
プロセスが完走した場合は、終了コードが非ゼロでも完走として記録する。
起動や実行管理に失敗した場合は、失敗の分類とメッセージを記録する。

同じ実行へ複数の判定がある場合の解釈規則として、ファイル内で最後に追記された判定を有効とする。
時計の変更に影響されないよう、発生時刻やUUIDの大小は判定順序に使わない。
v0.0.1 には、この規則を適用する射影を実装しない。

## 対話と終了状態

設定の `record_prompt` は、プロンプト全文を記録できるかを指定する。
既定値は無効であり、有効にした場合もタスクごとに記録するか確認する。

タグ候補には、設定した候補を先に並べ、その後へイベント履歴のタグを新しい順で加える。
入力では候補番号と自由タグをカンマ区切りで併用でき、空入力は未分類として扱う。
候補に存在しない数値はタグとして記録せず、無視する。
プロファイルの選択では、エージェントを起動せず `/usr/bin/true` を実行する `test` プロファイルを常に1番目へ置く。
既存の設定に `test` プロファイルがなくても、実行時に安全なテストプロファイルを補う。
`test-default` という識別子は安全なテスト用に予約し、設定に同じ識別子があっても正規のテストプロファイルへ置き換える。
実行確認で No を選んだ場合はプロファイルの選択へ戻らず、タスク受領だけを記録して終了コード0で終了する。

プロセスが完走した場合、終了コードにかかわらず受け入れるかを質問する。
受け入れ判定の既定値は Accepted とし、空入力では受け入れとして記録する。
実行中にキャンセルした場合はキャンセル状態の実行イベントを記録し、判定を質問せず終了コード130を返す。
実行管理に失敗した場合は失敗状態の実行イベントを記録し、判定を質問せず終了コード1を返す。

タスク受領または指名を記録できなければ、エージェントCLIを起動しない。
実行後の記録に失敗した場合は実行結果を表示し、記録失敗を示す終了コード1を優先する。
