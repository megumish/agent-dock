# 0.1.0-alpha.3

0.1.0-alpha.3 は、評価イベントから実行プロファイル別のスコアカードを計算し、プロファイル選択画面へ表示する。
助言、提案と承認のイベント、実支出の取得、過去の判定を訂正する入口は実装しない。
0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## API 世代

設定 API は `agent-dock/config/v1alpha3`、JSONL イベント形式は `agent-dock/events/v1alpha2` で識別する。
0.1.0-alpha.2 の形式は移行しない。
非対応の設定またはイベントを検出した場合は、既定値 No で一度だけ確認し、Yes の場合だけ元データを退避して現行形式へ切り替える。
No または割り込みの場合は元データを変更しない。
履歴訂正前の `schema_version` を持つ設定とイベントは移行せず、それぞれ非対応データとして同じ確認と退避の対象にする。

## 実行プロファイル

設定から手入力の `id` と内部実装名である `adapter` を除き、CLI を `cli` として宣言する。
利用者が指定する項目は、表示名、CLI、任意の実行可能ファイル上書き、任意のモデル、追加引数である。
表示名の前後空白、同じ表示名、同じ宣言内容の重複、異なる宣言から同じ ID が生成された場合、設定中の `test` CLI は拒否する。
追加引数はイベントへ記録されるため、秘密を含めてはならない。

プロファイル ID は、CLI、実行可能ファイル上書き、モデル、順序を保った追加引数を正準化し、固定名前空間の UUIDv5 として生成する。
表示名、PATH から解決した実行可能ファイル、観測した CLI の版、CLI が実際に選んだ既定モデルは ID に含めない。
ID の算出対象を変えると別 ID となり、以前の証拠は表示対象から外れる。

実行イベントは、宣言内容と解決済み実行可能ファイルを分けて記録する。
イベント内の宣言から再計算した ID が記録 ID と一致しない場合、または現在の同じ ID が異なる宣言を持つ場合は、その実行を射影から除外して警告する。
安全なテストプロファイルは設定へ保存せず、固定 ID で常に選択肢の先頭へ生成する。

## スコアカード

スコアカードは、現在選択できるプロファイルについて、全体と現在のタスクの各タグを表示する。
タグがない場合は、全体と未分類を表示する。
表示するタグは入力順の重複を除いた先頭 5 件とし、残りの件数を示す。

集計単位はタスクではなく実行である。
受入率は判定を持つ実行だけを母数にし、同じ実行に複数の判定がある場合はファイル内で最後の判定だけを有効とする。

所要時間は、最後の判定が Accepted であり、完走した実行だけを母数にする。
値は乗組員の実行開始から終了までの実測時間であり、表示値は中央値とする。
Rejected、未判定、キャンセル、実行管理失敗は所要時間へ含めない。

実支出は取得しないため、常に `Cost missing (0)` と表示する。
三軸のどれにも入らない実行は `Excluded` として件数を示す。

## 確認用データ

`mise run sample [scenario]` は、既定のイベントログを架空データで置き換える開発用ツールである。
一通りのスコアカード表示を確認する場合は `mise run sample` を使う。
実行前にすべての agent-dock を終了する必要がある。

既存ログがある場合は、変更されていないことを確認して同じディレクトリへ退避する。
退避と配置の間に別プロセスがログを作成した場合は、そのログを残して失敗する。

## 依存関係

既存の `uuid` crate で UUIDv5 feature を有効にし、推移的依存として `sha1_smol` が加わる。
UUIDv5 はプロファイル識別用であり、暗号学的な安全性へ依存する用途には使わない。

## 0.1.0 までに解消する事項

実行時の CLI の版と、CLI が実際に選んだ既定モデルをまだ観測しない。
0.1.0 のリリース前に、これらをイベントへ記録できるようにする。

開発用の架空データ生成ツールは、0.1.0 のリリース前に削除するか、実データから隔離する。
