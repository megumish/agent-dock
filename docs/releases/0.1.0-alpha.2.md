# 0.1.0-alpha.2

0.1.0-alpha.2 は、実際の仕事から評価に必要な観測を貯めるため、評価イベントの追記と受け入れ判定を実装する。
スコアカード、助言、過去の判定を訂正する入口、実支出の取得は実装しない。
対応 OS は macOS に限り、ほかの OS での動作は保証しない。

## API 世代と保存場所

設定 API は `agent-dock/config/v1alpha2`、JSONL イベント形式は `agent-dock/events/v1alpha1` で識別する。
alpha の間は形式の探索を優先し、異なる世代を読み替えず、移行もしない。

非対応の設定 API を検出した場合は、検出値と期待値を示し、既定値 No で作り直すか一度だけ確認する。
Yes の場合は旧設定全体を同じディレクトリへバックアップし、現在の既定設定へ原子的に置き換える。
置換した設定ではプロンプト記録を無効にする。
No、割り込み、書き込み失敗、確認中の旧設定の変化では旧設定を変更しない。
履歴訂正前の数値 `schema_version` を持つ設定は移行せず、非対応の設定として同じ確認と退避の対象にする。

イベントは `~/Library/Application Support/agent-dock/events.jsonl` へ JSONL 形式で保存する。
非対応のイベント形式を検出した場合は、形式と件数を示し、既定値 No でログを作り直すか一度だけ確認する。
Yes の場合は、現行形式のイベントが混在していてもログ全体を同じディレクトリへバックアップし、空の履歴から続行する。
No、割り込み、確認中のログ変更ではログを変更せず終了する。
壊れた JSON または現行形式として解釈できない行だけなら、ログを作り直さず警告して読み飛ばす。
履歴訂正前の `schema_version` を持つイベントは移行せず、非対応のイベントとしてログ全体の確認と退避の対象にする。

新規の設定、イベント、ロック、バックアップの各ファイルは権限 `0600` で作成する。
複数プロセスによる設定置換とイベント操作は、削除せず維持するロックファイルで直列化する。

イベントの各行は、イベントとタスクの UUIDv7、UTC の発生時刻、イベント種別、種別ごとのデータを持つ。

```json
{"format_version":"agent-dock/events/v1alpha1","event_id":"019...","task_id":"019...","occurred_at":"2026-08-02T14:00:00Z","kind":"task_received","data":{"tags":["rust"],"prompt":null,"prompt_chars":12}}
```

## 評価イベント

agent-dock は次の四種類を記録する。

- **タスク受領**：自由タグ、プロンプト本文または `null`、プロンプトの文字数を記録する。
- **指名**：ユーザーが実行を確認したプロファイルの識別子を記録する。
- **実行**：実際に使ったプロファイル、作業ディレクトリ、開始時刻、所要時間、終了状態を記録する。
- **受け入れ判定**：対象の実行イベントと、受け入れまたは拒否を記録する。

実行プロファイルには、解決した絶対実行パス、モデル、設定した追加引数を含める。
環境変数、内部で組み立てた引数列、標準出力、標準エラー、成果物は記録しない。
実支出は取得せず、実行イベントの `cost` を常に `null` とする。

同じ実行へ複数の判定がある場合は、ファイル内で最後に追記された判定を有効とする。
0.1.0-alpha.2 には、この規則を適用する射影を実装しない。

## 対話と終了状態

設定の `record_prompt` はプロンプト全文を記録できるかを指定し、既定値は無効とする。
有効にした場合もタスクごとに記録するか確認する。
タグ候補には設定した候補を先に並べ、その後へイベント履歴のタグを新しい順で加える。

エージェントを起動せず `/usr/bin/true` を実行する安全な `test` プロファイルを常に選択肢の先頭へ置く。
実行確認で No を選んだ場合は、タスク受領だけを記録して終了コード 0 で終了する。

プロセスが完走した場合は、終了コードにかかわらず結果を受け入れるか質問する。
受け入れ判定の既定値は Accepted とする。
実行中にキャンセルした場合はキャンセル状態を記録し、判定を質問せず終了コード 130 を返す。
実行管理に失敗した場合は失敗状態を記録し、判定を質問せず終了コード 1 を返す。
