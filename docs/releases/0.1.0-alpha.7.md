# 0.1.0-alpha.7

0.1.0-alpha.7 は、スコアカードを根拠に候補の実行プロファイルを提示する助言を実装し、0.1.0 の循環（指示、助言、承認または指名、遂行、記録、射影）の全要素を揃える。
0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## API 世代と移行

設定 API は `agent-dock/config/v1alpha4` のまま変更しない。
JSONL イベント形式は `agent-dock/events/v1alpha4` へ更新した。
助言の提案、承認、拒否、指名を表すイベントの追加と、`assigned` の廃止を含む非互換な変更である。

非対応世代のイベントを検出した場合、既定の対話コマンドだけが既定値 No の確認を表示し、承認された場合だけ読み取った版が変わっていないことを確認して退避する。
`agent-dock scorecard` と `agent-dock judge` が確認を表示して退避していた実装を、0.1.0-alpha.6 の文書に定めたとおり、確認を表示せずイベントログを変更しないままエラー終了するよう修正した。
`agent-dock observe` の挙動は変更しない。

## 助言

タスクのタグ確定後、指示と同じタグ（タグなしの指示はタグなし区分）のスコアカードを参照し、候補の実行プロファイルを一件提示するか、判断保留を返す。

- 候補の母集団は、その場で選択できるヘッドレス実行プロファイルに限る。対話型プロファイルは候補にしない。
- 候補の条件は、参照するすべてのタグ区分で受け入れ判定済み件数が閾値（3 件）以上であることとする。
- 候補は、すべての参照区分で受入率が単独最高のプロファイルが一意に定まる場合だけ提示する。
  受入率の比較は分数の交差積による整数比較で行い、所要時間と実支出は順位づけに使わない。
- 判断保留は、実績なし、件数不足、首位不定の順に判定した理由を区別し、理由とともに表示する。
- 候補には、参照したスコアカードの根拠値（受入率と判定済み件数、所要時間、実支出、軸ごとの直近実行日時）を添える。
- 助言の計算は指示タグ全件の区分を対象とし、スコアカード表示の五タグ制限を適用しない。
- 射影と助言のタグ比較は前後の空白を無視し、大文字小文字を区別する。
  空白のみのタグは区分を作らず、タスクのタグがすべて空白のみの場合は未分類として扱う。
  0.1.0-alpha.6 までの射影は空白を無視せず比較していた。記録済みイベントのタグ値そのものは変更しない。

番号選択の既定値は、提案時は候補プロファイル、判断保留時は従来どおり先頭のプロファイルになる。

## 助言イベント

実行確認で承認した時点で、タスク受付、助言、応答のイベントを一括で追記する。

- `advised`: 参照区分、提案（候補プロファイルと根拠値）または判断保留（理由）、適用した閾値を記録する。
- `approved`: 提案候補をそのまま受けた場合に記録する。
- `declined` と `designated`: 提案と異なるプロファイルを選んだ場合に、この順で記録する。
- `designated`: 判断保留時の指名は単独で記録する。

応答イベントは `advice_event_id` で同じ追記内の `advised` を参照する。
一括追記はイベントログの版を比較する CAS で行い、確認の間に履歴が変わった場合は射影と助言を再計算して提示からやり直す。
一連のイベントを永続化できない場合は実行を開始しない。
`assigned` イベントは廃止した。実行対象の決定は `approved` または `designated` が表す。

## 制限

- 実行に至らなかった提案（実行確認で No を選んで再編集した場合、確認中に中断した場合）は記録しない。
- 判断保留の件数閾値は定数であり、設定では変更できない。
- 実支出は引き続き取得せず、スコアカードと助言の根拠では欠測として明示する。
