# 0.1.0-alpha.4

0.1.0-alpha.4 は、実行確認でタスクを再編集する流れと、過去の完走またはキャンセル実行へ新しい受け入れ判定を追記する入口を追加する。
0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## API 世代

設定 API は `agent-dock/config/v1alpha3`、JSONL イベント形式は `agent-dock/events/v1alpha2` であり、0.1.0-alpha.3 から変更しない。
製品版の更新だけを理由に設定またはイベントを作り直す必要はない。
非対応の設定またはイベントを検出した場合の既定値 No の確認と退避手順は 0.1.0-alpha.3 から維持する。

## 実行確認と再入力

`Run this task? [Y/n]` に `n` または `no` と答えると、直前のタスク内容を編集可能な初期値としてタスク入力へ戻る。
戻る前に `Warning: Task was not run.` を表示し、続けて `Returning to task definition...` と案内する。
この時点ではエージェント CLI を起動せず、イベントも記録しない。

タスク内容とタグは直前の値を編集可能な初期値として再表示する。
プロンプト本文を記録するかの確認と実行プロファイルは再入力する。
実行を承認した時点の新しいタスク ID と時刻で `task_received` と `assigned` を追記してから CLI を起動する。
No と再入力を繰り返しても、未実行タスクのイベントは残らない。

再入力時に Ctrl-C または EOF を入力した場合は、エージェント CLI を起動せず終了する。

## 過去実行の判定

`agent-dock judge` は、イベントログ内の完走またはキャンセルした実行を新しい順で一覧する。
現在の設定やエージェント CLI のインストール状態には依存せず、実行時に記録したプロファイルを表示する。

一覧には、実行イベント ID、開始日時、プロファイル名、CLI、モデル、プロファイル ID、終了状態、タグ、現在有効な判定を表示する。
永続化された文字列の端末制御文字はエスケープする。
実行管理失敗は対象に含めない。

対象の選択と新しい `accepted` または `rejected` の入力には既定値を置かない。
選択した実行と現在有効な判定、新しい判定を表示し、追記の確認を受けてから `judged` イベントを一件だけ追記する。
既存の実行イベントと判定イベントは変更しない。
確認中に別プロセスが現在判定を変更した場合は、変更後の判定を表示して再確認する。
`q`、Ctrl-C、EOF、または最後の確認で No を選んだ場合はイベントを追記せず終了する。

複数の判定が同じ実行を参照する場合、イベントログ内で最後に追記された判定を現在有効とする。
この規則はスコアカードと過去実行一覧で共有する。

キャンセル実行は一覧で `cancelled` と表示し、後日初めて判定を付ける場合も、既存判定を訂正する場合も完走実行と同じ入口を使う。
実行をキャンセルした直後には判定を求めない。
判定を持つキャンセル実行は受入率の母集団へ含めるが、所要時間の母集団には含めない。

## 維持する挙動

実行プロファイル、スコアカード、実行直後の受け入れ判定、確認用データの仕様は、上記の変更を除いて 0.1.0-alpha.3 から変更しない。
実支出は引き続き取得しない。
