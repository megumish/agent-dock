# 0.1.0

0.1.0 は、評価と采配の循環の全要素を備えた最初の実用版である。
指示の受付、スコアカードを根拠とする助言、ユーザーの承認または指名、エージェント CLI のヘッドレス実行、直接実行の観測、評価イベントの追記記録、スコアカードへの射影を、一つのループとして提供する。
各機能が成立した時点の詳細な挙動は、`docs/releases/` の各開発確認版（0.1.0-alpha.1 から 0.1.0-alpha.10）のリリース文書に記録している。

## 対応環境と API 世代

- 対応 OS は macOS に限り、ほかの OS での動作は保証しない。
- 設定 API は `agent-dock/config/v1alpha4`、JSONL イベント形式は `agent-dock/events/v1alpha6` であり、0.1.0-alpha.10 から変更しない。
  非対応世代の検出時の挙動（既定の対話コマンドだけが既定値 No の確認・退避を行い、`scorecard`、`judge`、`observe` は確認なしでエラー終了する）も変更しない。
- 0.2.0 以降の拡張は、DESIGN の定めるとおり ADR を作成してから実装する。

## 0.1.0 の範囲

- **仲介実行**: Claude Code、Codex CLI、Gemini CLI、Antigravity CLI のヘッドレス実行を機械可読出力で起動し、所要時間、申告値、観測した CLI 版とモデルを記録する。
  実支出は、どの CLI も公式の機械可読経路で実額を提供しないため、取得せず欠測として明示する。
- **直接実行の観測**: ユーザーが直接起動した Claude Code と Codex CLI のセッションを hook で観測し、明示マークによるタスク境界と受け入れ判定を、仲介実行と同じ評価基盤へ取り込む。
- **記録と射影**: 評価イベントをローカルに追記で保持し、受入率、所要時間、実支出の三軸と申告値の開示を持つスコアカードへ射影する。
- **助言**: 指示と同じタグの実績に基づき候補の実行プロファイルを提示するか、証拠が不足しているか候補を一意に選べない場合は理由とともに判断保留を返す。
  提案（`advised`）、承認（`approved`）、拒否（`declined`）、指名（`designated`）、実行（`executed`）、受け入れ判定（`judged`）は、個別のイベントとして追記される。
  エージェントを起動しない安全なテストプロファイルは候補にしない。

## 制限と非主張

- 0.1.0 は VISION の成功基準に基づく成功を主張しない。成功を主張するには、成功基準に従う事前登録が先に必要である。
- 資格、探索、リプレイ、評価の代行、再審査、エスカレーションなどは実現していない。
  一覧は DESIGN の「0.1.0 で実現しない VISION の要求」を正本とする。
- 未決事項と将来の作業候補は GitHub Issue で追跡する。
