# v0.0.2

v0.0.2 は、評価イベントから実行プロファイル別のスコアカードを計算し、プロファイル選択画面へ表示する。
助言、提案と承認のイベント、実支出の取得、過去の判定を訂正する入口は実装しない。
v0.0 が完成するまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## 更新前の注意

初回起動前に、動作中の v0.0.1 の agent-dock をすべて終了する必要がある。
設定とイベントの `schema_version` は `0.0.2` となり、v0.0.1 の形式は移行しない。
異なる版の設定は同じディレクトリへ退避して既定設定へ置き換え、異なる版を含むイベントログはログ全体を退避して空の履歴から始める。
退避直前に対象が変化した場合は、変更後の内容を再読込する。

## 実行プロファイル

設定から手入力の `id` と内部実装名である `adapter` を除き、CLI を `cli` として宣言する。
利用者が指定する項目は、表示名、CLI、任意の実行可能ファイル上書き、任意のモデル、追加引数である。
表示名の前後空白、同じ表示名、同じ宣言内容の重複、異なる宣言から同じ ID が生成された場合、設定中の `test` CLI は拒否する。
追加引数はイベントへ記録されるため、秘密を含めてはならない。
認証情報には各 CLI の資格情報ストアを使う。

プロファイル ID は、CLI、実行可能ファイル上書き、モデル、順序を保った追加引数を正準化し、固定名前空間の UUIDv5 として生成する。
表示名、PATH から解決した実行可能ファイル、観測した CLI の版、CLI が実際に選んだ既定モデルは ID に含めない。
設定内容を変えると、表示名が同じでも別 ID となり、以前の証拠は表示対象から外れる。
小さな構成変更をまたぐ証拠の系譜と適用可能性は、v0.1 以降で扱う。

実行イベントは、宣言内容と解決済み実行可能ファイルを分けて記録する。
イベント内の宣言から再計算した ID が記録 ID と一致しない場合、または現在の同じ ID が異なる宣言を持つ場合は、その実行を射影から除外して警告する。
安全なテストプロファイルは設定へ保存せず、固定 ID で常に選択肢の先頭へ生成する。

## スコアカード

スコアカードは、現在選択できるプロファイルについて、全体と現在のタスクの各タグを表示する。
タグがない場合は、全体と未分類を表示する。
表示するタグは入力順の重複を除いた先頭5件とし、残りの件数を示す。
過去の複数タグを持つ実行は、該当する各タグへそれぞれ含める。

集計単位はタスクではなく実行である。
受入率は判定を持つ実行だけを母数にし、判定は `execution_event_id` で既存の実行へ対応付ける。
判定側の `task_id` は対応付けに使わず、同じ実行に複数の判定がある場合はファイル内で最後の判定だけを有効とする。
この規則は v0.0.2 の射影で初めて適用される。

所要時間は、最後の判定が Accepted であり、完走した実行だけを母数にする。
値は乗組員の実行開始から終了までの実測時間であり、タグ入力、記録確認、プロファイル選択、実行確認に要した利用者の時間を含まない。
表示値は中央値である。
Rejected、未判定、キャンセル、実行管理失敗は所要時間へ含めない。

実支出は引き続き取得しないため、常に `Cost missing (0)` と表示し、直近日時を付けない。
各軸の直近日時は、その軸の母数へ入った実行の開始時刻の最大値である。
直近日時は現在からの秒、分、時、日の最大単位を切り捨てて表示する。
三軸のどれにも入らない実行は `Excluded` として件数を示す。

## 確認用データ

`mise run sample [scenario]` は、既定のイベントログを架空データで置き換える開発用ツールである。
一通りのスコアカード表示を確認する場合は、次のコマンドを使う。

```console
mise run sample
```

シナリオを省略すると `showcase` を使う。
`showcase` は `few`、`many-tags`、`rejections`、`rejudged`、`mixed-outcomes` を safe-test と四つの既定プロファイルへ一つずつ割り当て、一つの現行スキーマのログへまとめる。
画面には、safe-test と現在の環境で実行可能な既定プロファイルだけが表示される。
`empty` と `old-schema` は、ほかのデータと同時に成立しない状態を確認するため、個別に指定する。
実行前にすべての agent-dock を終了する必要がある。

既存ログがある場合は、変更されていないことを確認して同じディレクトリへ退避する。
一時ログの最終配置は既存ファイルを上書きしない操作を使う。
退避と配置の間に別プロセスがログを作成した場合は、そのログを残して失敗する。
失敗時は表示された退避ファイルから手動で復元できる。
実際の仕事へ使い始める前に、このツールを削除または実データから隔離する。

## 依存関係

既存の `uuid` crate で UUIDv5 feature を有効にし、推移的依存として `sha1_smol` が加わる。
UUIDv5 の規定アルゴリズムを独自実装せず、既存依存の機能を使うための追加である。
`sha1_smol` はプロファイル識別用であり、暗号学的な安全性へ依存する用途には使わない。
ビルドスクリプトや `unsafe` を追加せず、対象の Rust 版でコンパイルできることを確認する。

## 既知の不足

v0.0.2 は、実行時の CLI の版と、CLI が実際に選んだ既定モデルを観測しない。
したがって、同じ ID のまま CLI や既定モデルが変化し得る。
実際の仕事へ使い始める前に、これらをイベントへ記録できるようにする。
