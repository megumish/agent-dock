# 0.1.0-alpha.6

0.1.0-alpha.6 は、ユーザーが直接起動した Claude Code と Codex CLI の対話セッションを、仲介実行と共通の評価イベントへ取り込む。
直接実行はドックが起動または承認せず、セッション、明示したタスク境界、観測できた構成、補助実測を追記する。
0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## API 世代と移行

設定 API を `agent-dock/config/v1alpha4`、JSONL イベント形式を `agent-dock/events/v1alpha3` へ更新した。
対話型プロファイル、実行基盤、実行元、来歴、セッション、観測タスク、構成、帰属、補助実測、観測異常を表すための非互換な変更である。

非対応世代の設定またはイベントを検出した場合は、従来と同じく既定値 No の確認を表示する。
ユーザーが作り直しを承認した場合だけ、読み取った版が変わっていないことを確認して退避し、新しい既定設定または空のイベントログへ置き換える。

## 対話型プロファイル

実行プロファイルへ `headless` と `interactive` の実行基盤を追加した。
既定設定には、従来の四つのヘッドレス実行プロファイルに加え、Claude Code と Codex CLI の対話型プロファイルを一つずつ含める。
対話型プロファイルはドックから起動しないため、実行可能ファイルと起動引数を持たない。
モデルと `identity` の値は、直接実行を一意に帰属させる構成指紋として使う。

## セッションと明示的なタスク境界

`agent-dock observe` に、セッションの開始、再開、終了、検索と、タスクの開始、完了、中断を追記するコマンドを追加した。
外部セッション ID は CLI 種別と組み合わせて一つのローカルセッション ID へ対応付け、別のローカル ID への再割り当てを拒否する。
終了済みセッションへ遅れて届いた開始通知は、再開通知へ読み替えず拒否する。

一つのセッションで進行中のタスクは一つに限る。
開始がない終了マークは成功扱いにせず、孤立終了の観測異常を追記してコマンドを失敗させる。
セッション終了は進行中タスクの完了または中断を推測しない。

タスク開始と終了の一連のイベントは、イベントログの版を比較する CAS とファイルロックの下で一括追記する。
追記は一時ファイルの同期と原子的な置換を使い、競合時は履歴を再読して判定をやり直す。
解釈できない現在世代の行がある履歴へは観測イベントを追加しない。

## hook による観測

Claude Code の `SessionStart`、`SessionEnd`、`CwdChanged`、`StopFailure` と、Codex CLI の `SessionStart`、`SessionEnd`、`Stop` を受け取る標準入力コマンドを追加した。
hook の入力は 1 MiB を上限とし、未知のイベント、形式不正、上限超過を入力内容を含まない固定エラーへ変換する。

セッション開始または Stop がモデルと権限モードを提供した場合は、その許可項目だけを最新のセッション構成として保持する。
明示タスクの開始でプロファイルを指定しなかった場合はその時点の最新構成を使い、終了ではタスク開始後に改めて届いた構成だけを使う。
モデルまたはプロファイルが要求する識別項目が欠測した場合、開始と終了で構成が変わった場合、該当プロファイルがない場合、複数候補が残る場合は、自動帰属しない。

hook から会話記録のパス、ユーザー入力、エージェントの応答、ツールの引数と出力を保存しない。
未知の JSON 項目も正規化結果へ保持しない。

## OpenTelemetry の補助事実

Claude Code と Codex CLI の OTLP/HTTP JSON Logs ペイロードを標準入力から取り込むコマンドを追加した。
Claude Code では API 要求の区間、セッション識別子、モデル、入出力トークン量、推定コストを許可する。
Codex CLI では API 要求の区間と会話識別子を許可する。
入力上限は hook と同じく 1 MiB であり、秘密を含みうる未知の属性は保存しない。

補助事実の発生区間が一つの完了済み明示タスク区間へ完全に含まれる場合だけ、そのタスクへ関連付ける。
対応するセッションがない場合、境界をまたぐ場合、候補が一意でない場合は補助実測へ変換せず、相関できない補助事実の観測異常を追記する。
遅れて到着したペイロードも、受信時刻ではなくソース時刻で関連付ける。

推定コストは実支出ではないため、スコアカードの実支出軸へ加えない。
この版は OTLP の HTTP 受信サーバーを内蔵せず、JSON ペイロードをファイル出力またはローカル Collector から標準入力へ渡す。

## 帰属、判定、スコアカード

構成が登録済みの対話型プロファイルへ一意に一致し、正常完了した直接実行だけを、仲介実行と同じスコアカードへ含める。
スコアカードは仲介実行と直接実行の件数を実行元別に保持し、進行中、中断、時刻不正、構成欠測、構成変更、該当なし、曖昧一致による除外件数を区別する。
`agent-dock scorecard` は、ヘッドレスと対話型を含むすべての登録済みプロファイルを表示する。

`agent-dock judge` は、帰属済みで完了した直接実行も判定候補に含める。
判定と帰属訂正はタスク ID を対象に新しいイベントを追記し、同じタスクでは最後のイベントを現在値とする。
過去の観測事実は上書きしない。

## 制限

タスク境界は hook の Stop や OpenTelemetry から推測せず、ユーザーまたは連携スキルが明示する必要がある。
hook が必要な構成項目をタスク開始後に再通知しない場合は、タスク開始と終了の両方で対話型プロファイルを明示申告するか、完了後に帰属を訂正する必要がある。
補助実測は現在のスコア軸を増やさず、実支出も引き続き取得しない。
助言はまだ実装しない。
