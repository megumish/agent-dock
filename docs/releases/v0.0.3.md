# v0.0.3

v0.0.3 は、実行確認でタスクを再編集する流れと、過去の完走実行へ新しい受け入れ判定を追記する入口を追加する。
v0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

## 更新前の注意

初回起動前に、動作中の v0.0.2 の agent-dock をすべて終了する必要がある。
設定とイベントの `schema_version` は `0.0.3` となり、v0.0.2 の形式は移行しない。
異なる版の設定は同じディレクトリへ退避して既定設定へ置き換え、異なる版を含むイベントログはログ全体を退避して空の履歴から始める。

## 実行確認と再入力

`Run this task? [Y/n]` に `n` または `no` と答えると、直前のタスク内容を編集可能な初期値としてタスク入力へ戻る。
この時点ではエージェント CLI を起動せず、`task_received`、`assigned`、`executed`、`judged` のいずれのイベントも記録しない。

編集後も最初に入力したタグを保持する。プロンプト本文を記録するかの確認と実行プロファイルは再入力する。
タスクの変更に応じて記録範囲と実行先を見直せるようにするためである。
実行を承認した時点の新しいタスク ID と時刻で `task_received` を記録し、続けて同じタスク ID の `assigned` を追記してから、選択したエージェント CLI を起動する。
No と再入力を繰り返しても、未実行タスクのイベントは残らない。

再入力時に Ctrl-C または EOF を入力した場合は、エージェント CLI を起動せず終了する。

## 過去実行の判定

`agent-dock judge` は、イベントログ内の完走した実行を新しい順で一覧する。
現在の設定やエージェント CLI のインストール状態には依存せず、実行時に記録したプロファイルを表示する。

一覧には、実行イベント ID、開始日時、プロファイル名、CLI、モデル、プロファイル ID、終了コード、タグ、現在有効な判定を表示する。
永続化された文字列の端末制御文字はエスケープする。
対象は終了コードの有無や値を問わない `completed` 実行とし、キャンセルと実行管理失敗は含めない。
対象がない場合はイベントを追記せず正常終了する。

対象の選択と新しい `accepted` または `rejected` の入力には既定値を置かない。
選択した実行と現在有効な判定、新しい判定を表示し、追記の確認を受けてから `judged` イベントを一件だけ追記する。
新しい判定は対象実行の `task_id` と `execution_event_id` を参照し、既存の実行イベントと判定イベントを変更しない。
確認中に別プロセスが現在判定を変更した場合は、変更後の判定を表示して再確認する。
`q`、Ctrl-C、EOF、または最後の確認で No を選んだ場合はイベントを追記せず終了する。

複数の判定が同じ実行を参照する場合、イベントログ内で最後に追記された判定を現在有効とする。
この規則はスコアカードと過去実行一覧で同じ処理を共有する。

キャンセルした実行への後日判定は、この版では対象外とする。

## v0.0.2 から維持する挙動

実行プロファイルとスコアカード、実行、実行直後の受け入れ判定、確認用データの仕様は、上記の変更を除いて v0.0.2 から変更しない。
実支出は引き続き取得しない。
