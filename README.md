# agent-dock

agent-dock は、ローカルで制御するマルチエージェント環境を構築するプロジェクトである。
本プロジェクトでは、この環境を**ドック**と呼ぶ。
ドックは、AI モデルとツール、権限、実行基盤の組み合わせを**実行プロファイル**として登録し、実際の仕事で評価して役割ごとに使い分ける。

外部ベンチマークだけに頼らず、ユーザー自身の仕事から得た実測を証拠として蓄積する。
蓄積した証拠に基づき、「このタスクには、どのモデルを、どの構成で使えば十分な品質を適切なコストで得られるか」を判断できるようにする。
そのために、実際の仕事から適性判断に使う**スコア**を導く**評価**と、スコアに基づいて指示の委任先を選ぶ**振り分け**を同じ基盤で扱う。
ドックが起動または仲介するすべての仕事を**評価イベント**として記録し、最終判断は常にユーザーが下す。
理念と概念モデルの詳細は [VISION.md](./VISION.md) に記す。

実装は v0.0.x の開発確認版で評価と采配の循環を組み立て、最小のループが揃った版を v0.1.0 としてリリースする。
以後のマイルストーンは v0.2.0、v0.3.0 と重ね、実際の運用で得た証拠に基づいて拡張する。

## 文書の役割と上下関係

文書は**VISION（最上位の規範）→ DESIGN（v0.1.0 の設計）→ ADR（v0.2.0 以降の決定と理由）→ 実装**の順に具体化する。
v0.0.x の期間は ADR を作らず、実装しながら技術を探索する。
下位の文書や実装を上位の文書と矛盾させることはできず、変更が必要な場合はユーザーの裁定により上位の文書から改定する。
依存関係の採用と更新には、バージョンを問わずプロジェクト全体の方針を適用する。
リリース文書は実装時点の事実を記録し、設計を定めない。

<!-- markdownlint-disable MD013 -->

| 文書 | 役割 |
| --- | --- |
| [VISION.md](./VISION.md) | 理念、概念モデル、原則、成功基準、非目標を定め、数値や実装方式を扱わない最上位の規範文書 |
| [DESIGN.md](./DESIGN.md) | 最初の実用版 v0.1.0 の構成と不変条件を定め、v0.1.0 で実現しない VISION の要求を列挙する設計文書 |
| [DEPENDENCIES.md](./DEPENDENCIES.md) | 外部 crate の採用、更新、再評価に適用するプロジェクト共通の方針 |
| [docs/releases/](./docs/releases/README.md) | 各版の実装範囲と運用上の挙動を記録するリリース文書 |
| `docs/adr/` | v0.2.0 以降の拡張で作成する決定と理由の記録であり、採択にはユーザーの承認が必要 |

## 実行

現在の実装範囲と挙動は [v0.0.3 のリリース文書](./docs/releases/v0.0.3.md) に記録する。
v0.1.0 としてリリースするまで、本実装と蓄積データは開発確認専用であり、実際の仕事への利用を前提としない。

Rust ツールチェーンは mise で管理する。

```console
mise install
mise run
```
