# agent-dock

ローカル環境で動くマルチエージェントの**ドック**を作るプロジェクト。複数の AI モデルを、ツール・権限・実行基盤といった構成と組み合わせた**実行プロファイル**として乗組員に受け入れ、実際の仕事の中で評価し、適所に配置する。

外部ベンチマークではなく自分の仕事での実測を証拠として蓄積し、「このタスクには、どのモデルを、どの構成で使えば十分賢く、十分安いか」を判断できるようにする。評価（実仕事から証拠を集めてスコアを導く）と振り分け（スコアに基づいて指示を適切なエージェントに委ねる）が対等な両輪であり、背骨は「すべての仕事が評価イベントとして記録される」こと。判断の最上位は常にユーザーにある。詳細は [VISION.md](./VISION.md)。

実装は [PLAN.md](./PLAN.md) の工程に従って進める（開始点は Phase 0）。

## ドキュメント構成

文書の層は **VISION（憲法）→ DESIGN（構成と選択肢）→ ADR（決定と理由）→ 実装**であり、PLAN がこの実現を段階化する。決定は ADR でのみ生まれ、上位の文書と矛盾する変更はできない（必要なら先に上位を改定する。裁定者はユーザー）。

| 文書 | 役割 |
|---|---|
| [VISION.md](./VISION.md) | 憲法。理念と概念モデル（評価イベント・射影・教師信号・証拠の序列・役割と資格・裁定・始動）、原則、成功基準、非目標を定める。数値や実装方式は書かない |
| [DESIGN.md](./DESIGN.md) | VISION を実装可能な構成に降ろす設計文書。設計不変条件・論理責務・クリティカルフローを固定し、実装方式は Decision Register（D-01〜D-24）に選択肢として開いたまま保持する。技術選定はしない。何が固定で何が未決かの正はここ |
| [PLAN.md](./PLAN.md) | 段階的実現の計画。Phase 0（意味契約・dummy-only）〜 5b（評価代行の解放）の工程と、各フェーズの入口 ADR・出口条件・継続運用レーンを定める。自律権限がいつ広がるかの正はここ |
| docs/adr/ | 決定と理由の記録（ADR）。Phase 0 で作り始める。採択の承認者はユーザー |
| [docs/research-notes.md](./docs/research-notes.md) | **非規範**の調査ノート。個別製品・版・現時点の傾きの日付つきスナップショット。ADR を拘束せず、列挙は網羅ではない。読まなくても VISION・DESIGN・PLAN と ADR だけで判断できる |

## 読み方

- はじめて読む場合: VISION → DESIGN の「読み方（記述の拘束力）」→ PLAN の順を推奨。
- 各記述がどこまで拘束するかは、本文に埋め込まれたマーカー（`INVARIANT` / `OPEN` / `NON-NORMATIVE`。無印は `FIXED`）が示す。定義は DESIGN の「読み方」の表。
